## 说明

老师要求最终提交的 PPT 需要包含：

- 实现思路。
- 关键代码片段解释。
- 程序运行结果展示。
- 结果分析。
- 使用提供的 PPT 模板制作。

本文件先不生成 PPT，只规划每一页应该放什么内容、重点讲什么、建议贴哪些代码或图片。后续正式制作 PPT 时，以这份逐页规划为核心依据，再结合个人讲述习惯进行压缩或调整。

建议总页数控制在 12 到 14 页之间。页数太少会讲不清楚类设计和验证过程，页数太多则容易显得拖沓。

## 第 3 页：ROC 与 AUC 基本原理

### 页面标题

ROC 曲线与 AUC 原理

### 页面内容

建议放三个公式或定义：

```text
TPR = TP / P
FPR = FP / N
AUC = ROC 曲线下面积
```

并用简短文字说明：

- 横轴是 `FPR`，表示负类被误判为正类的比例。
- 纵轴是 `TPR`，表示正类被正确识别的比例。
- 随机分类器对应对角线。
- 曲线越靠近左上角，分类器越好。

### 页面重点

这是后续算法的背景。不要讲太久，保证听众知道 `FPR`、`TPR` 和 `AUC` 是什么即可。

### 建议素材

可以放一张简化 ROC 示意图，也可以直接用本实验 `data2_ROC.png` 的局部作为例子。

### 讲述口径

“ROC 曲线本质上是在不同阈值下观察模型的召回正类能力和误判负类程度。AUC 则把整条曲线压缩成一个面积指标。”

## 第 6 页：ROC 计算算法选择

### 页面标题

ROC 计算：排序 + 同分组累计

### 页面内容

建议用流程图或编号步骤：

```text
1. 按 Scores 降序排序
2. 按相同得分分组
3. 从高到低扫描
4. 每处理一组，累计 TP 和 FP
5. 计算当前 FPR 和 TPR
6. 得到完整 ROC 点序列
```

同时放对比：

| 方法 | 思路 | 复杂度 |
|---|---|---|
| 逐阈值扫描 | 每个阈值重新扫全部样本 | 接近 `O(n^2)` |
| 当前方法 | 排序后增量累计 | `O(n log n)` |

### 页面重点

这是 PPT 技术核心页之一。要讲清楚为什么这样写更合理。

### 讲述口径

“最直观的方法是每个阈值都重新扫描全部样本，但效率较低。我采用的是先排序，再从高分到低分逐组累计。相同得分样本作为一组处理，这样既快，也能避免重复得分带来的顺序问题。”

## 第 7 页：computeROC 关键代码解释

### 页面标题

`computeROC()` 关键代码

### 页面内容

建议贴核心代码：

```text
[sortedScores, sortIndex] = sort(scores, 'descend');
sortedLabels = labels(sortIndex);
scoreChangeIndex = [find(diff(sortedScores) ~= 0); numel(sortedScores)];

for i = 1:numel(scoreChangeIndex)
    currentIndex = scoreChangeIndex(i);
    groupLabels = sortedLabels(previousIndex:currentIndex);

    truePositive = truePositive + sum(groupLabels == 1);
    falsePositive = falsePositive + sum(groupLabels == 0);

    tpr(i + 1) = truePositive / positiveCount;
    fpr(i + 1) = falsePositive / negativeCount;
end
```

页面右侧或下方写解释：

- `scoreChangeIndex` 用于找到每个同分组的边界。
- `truePositive` 和 `falsePositive` 是累计量。
- `i + 1` 是因为第一个 ROC 点保留给 `(0,0)`。

### 页面重点

讲清楚“同分组”和“增量累计”。

### 讲述口径

“排序后，得分相同的样本会相邻出现。每次处理一个同分组，把组内正类数量加到 TP，把负类数量加到 FP，再计算新的 TPR 和 FPR。”

## 第 8 页：极端阈值与重复得分处理

### 页面标题

极端阈值与重复得分处理

### 页面内容

建议放两块内容。

第一块：极端阈值

```text
+Inf -> 全部判为负类 -> (0,0)
-Inf -> 全部判为正类 -> (1,1)
```

第二块：重复得分

```text
相同 Scores 的样本必须一起进入预测正类集合
否则 ROC 曲线会受到同分样本排序影响
```

可贴代码：

```text
fpr = zeros(numel(scoreChangeIndex) + 2, 1);
tpr = zeros(numel(scoreChangeIndex) + 2, 1);

fpr(end) = 1;
tpr(end) = 1;
```

### 页面重点

这一页直接回应题目中的“必须处理得分完全相同样本”和“必须包含 +Inf / -Inf 极端情况”。

### 讲述口径

“题目中特别强调了重复得分和极端阈值。我这里把相同得分作为同一组处理，并显式保留起点和终点，保证 ROC 曲线完整。”
