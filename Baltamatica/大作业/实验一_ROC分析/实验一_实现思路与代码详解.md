# 实验一：自定义 ROC 分析类实现思路与代码详解

## 1. 实验目标

本实验要求在北太天元中设计一个名为 `MyROC` 的类。输入二分类问题的真实标签 `labels` 和预测得分 `scores` 后，程序需要完成以下任务：

1. 计算不同阈值下的假阳性率 `FPR` 和真阳性率 `TPR`。
2. 正确处理预测得分相同的样本。
3. 包含阈值为 `+Inf` 和 `-Inf` 时的两个极端状态。
4. 使用北太天元内置的 `trapz` 计算 AUC。
5. 绘制 ROC 曲线、随机分类器参考线，并标注 AUC。
6. 使用 `data1.mat`、`data2.mat`、`data3.mat` 测试程序。

最终代码只依赖北太天元支持的基础语法和绘图函数，不依赖 MATLAB、外部工具箱或第三方函数。

## 3. ROC 曲线的基本原理

对一个给定阈值 `threshold`，程序把满足下式的样本判为正类：

```text
scores >= threshold
```

在这个阈值下会得到四类统计量：

- `TP`：实际为正类，预测也为正类。
- `FP`：实际为负类，但预测为正类。
- `TN`：实际为负类，预测也为负类。
- `FN`：实际为正类，但预测为负类。

ROC 曲线使用的两个坐标为：

```text
TPR = TP / P
FPR = FP / N
```

其中 `P` 是正类样本总数，`N` 是负类样本总数。阈值从高到低变化时，被判为正类的样本越来越多，于是得到一系列 `(FPR, TPR)` 点。

理想分类器的 ROC 曲线接近左上角；随机分类器大致位于从 `(0,0)` 到 `(1,1)` 的对角线上。

## 4. AUC 的含义

AUC 是 ROC 曲线下面积。一般可作如下理解：

- `AUC = 1`：正负样本完全可分。
- `AUC > 0.5`：分类器整体优于随机猜测。
- `AUC = 0.5`：分类能力接近随机。
- `AUC < 0.5`：分类方向可能相反。

本实验严格按照题目要求调用：

```matlab
obj.AUC = trapz(obj.FPR, obj.TPR);
```

由于 `computeROC()` 生成的 `FPR` 按非递减顺序排列，可以直接进行梯形积分。

## 5. MyROC 类的结构

`MyROC` 中包含五个属性：

```matlab
properties (SetAccess = private)
    Labels
    Scores
    FPR
    TPR
    AUC
end
```

| 属性 | 作用 |
|---|---|
| `Labels` | 保存真实类别标签 |
| `Scores` | 保存分类器输出得分 |
| `FPR` | 保存 ROC 曲线横坐标 |
| `TPR` | 保存 ROC 曲线纵坐标 |
| `AUC` | 保存 ROC 曲线下面积 |

`SetAccess = private` 表示外部程序可以读取这些属性，但不能直接修改。这样可以避免输入数据被改动后，`FPR`、`TPR` 和 `AUC` 没有同步更新。

类中包含四个方法：

| 方法 | 作用 |
|---|---|
| `MyROC(labels, scores)` | 构造对象并自动完成计算 |
| `computeROC(obj)` | 计算 ROC 曲线点 |
| `computeAUC(obj)` | 使用 `trapz` 计算 AUC |
| `plotROC(obj, plotTitle)` | 绘制 ROC 图并设置对应标题 |

## 6. 构造函数

构造函数代码为：

```matlab
function obj = MyROC(labels, scores)
    labels = labels(:);
    scores = scores(:);

    if numel(labels) ~= numel(scores)
        error('labels and scores must have the same number of elements.');
    end
    if any((labels ~= 0) & (labels ~= 1))
        error('labels must contain only 0 and 1.');
    end

    obj.Labels = labels;
    obj.Scores = scores;
    obj = obj.computeROC();
    obj = obj.computeAUC();
end
```

`labels(:)` 和 `scores(:)` 把输入统一转换成列向量。这样无论数据文件中保存的是行向量还是列向量，后续处理方式都一致。

构造函数随后进行题目要求的两项输入合法性检查：

- `numel(labels) ~= numel(scores)` 判断标签数和得分数是否一致。
- `any((labels ~= 0) & (labels ~= 1))` 判断是否存在不为 `0` 或 `1` 的标签。

检查通过后，列向量形式的输入分别存入 `Labels` 和 `Scores` 属性。

构造函数随后自动调用 `computeROC()` 和 `computeAUC()`。因此主程序只需要创建对象：

```matlab
rocObj = MyROC(data.labels, data.scores);
```

对象中就已经包含 `FPR`、`TPR` 和 `AUC`。

本实验只加入题目明确要求的长度和标签检查，没有扩展大量通用错误检测，代码仍保持简洁。

## 7. computeROC 算法

### 7.1 统计正负样本数

```matlab
positiveCount = sum(labels == 1);
negativeCount = sum(labels == 0);
```

后面分别用这两个数量计算 `TPR` 和 `FPR`。

### 7.2 按预测得分降序排序

```matlab
[sortedScores, sortIndex] = sort(scores, 'descend');
sortedLabels = labels(sortIndex);
```

得分最高的样本排在前面。阈值不断降低的过程，就等价于按排序结果从前向后逐渐把样本加入“预测正类”集合。

### 7.3 找出同分组边界

```matlab
scoreChangeIndex = [find(diff(sortedScores) ~= 0); numel(sortedScores)];
```

这句代码的含义是：

1. `diff(sortedScores)` 计算相邻得分之差。
2. 差值不为零的位置表示当前得分组结束。
3. 最后补上样本总数，保证最低得分组也被记录。

相同得分的样本必须同时改变预测类别。如果把同分样本逐个处理，ROC 曲线会受到这些样本内部排序的影响。因此，程序只在每个同分组结束的位置记录 ROC 点。

### 7.4 使用累计和代替循环

最终版本使用累计和计算 TP 和 FP：

```matlab
cumulativeTP = cumsum(sortedLabels == 1);
cumulativeFP = cumsum(sortedLabels == 0);
tpr = [0; cumulativeTP(scoreChangeIndex) / positiveCount; 1];
fpr = [0; cumulativeFP(scoreChangeIndex) / negativeCount; 1];
```

这里：

- `sortedLabels == 1` 得到正类位置。
- `cumsum(sortedLabels == 1)` 得到扫描到每个位置时累计的 TP。
- `cumsum(sortedLabels == 0)` 得到累计的 FP。
- 只在 `scoreChangeIndex` 对应位置取值，就得到每个有效阈值的 ROC 点。

早期版本使用循环逐组累加。最终改成 `cumsum` 后代码更短，`data3.mat` 在北太天元中的运行速度也更快。

### 7.5 极端阈值

向量开头和结尾显式加入：

```text
(0,0) 和 (1,1)
```

它们分别对应：

```text
threshold = +Inf -> 所有样本判为负类 -> (0,0)
threshold = -Inf -> 所有样本判为正类 -> (1,1)
```

处理完最低得分组后通常已经到达 `(1,1)`，因此最后加入的 `-Inf` 端点可能与前一个点重合。这个重复点不会改变 AUC，因为相邻两点的横坐标差为零，但它明确满足了题目对两个极端阈值的要求。

### 7.6 算法效率

逐个阈值重新扫描全部样本的复杂度接近 `O(n^2)`。当前方法主要开销是排序，复杂度约为：

```text
O(n log n)
```

排序之后的累计和和索引操作均为线性过程，更适合 `data3.mat` 这种样本量较大的数据。

## 8. computeAUC

代码只有一行：

```matlab
obj.AUC = trapz(obj.FPR, obj.TPR);
```

`trapz` 把相邻 ROC 点之间的区域视为梯形，再将每个梯形面积相加。因为起点、终点和同分组都已在 `computeROC()` 中处理完成，所以这里不需要额外排序或修正。

## 9. plotROC 绘图设计

最终绘图代码保持简单：

```matlab
function plotROC(obj, plotTitle)
    figure;
    plot(obj.FPR, obj.TPR, 'b-');
    hold on;
    plot([0 1], [0 1], 'r--');
    hold off;

    xlabel('False Positive Rate');
    ylabel('True Positive Rate');
    title(plotTitle);
    legend('ROC Curve', 'Random Classifier');
    text(0.62, 0.12, ['AUC = ' num2str(obj.AUC, '%.4f')]);
    grid on;
    axis([0 1 0 1]);
end
```

图中包含：

- 蓝色实线：实际 ROC 曲线。
- 红色虚线：随机分类器参考线。
- 横纵坐标名称。
- 与数据文件对应的标题。
- 图例、网格和 AUC 数值。
- 固定坐标范围 `[0,1]`。

绘图全部使用北太天元默认字体、默认字号和默认线宽。早期版本设置了字体大小、线宽、背景色、图例位置和文本边框，但北太天元在连续渲染多张复杂图时响应较慢。去掉这些非必要样式后，三张图可以快速连续生成，同时仍满足题目要求。

标题通过参数 `plotTitle` 传入，并在 `plotROC()` 内部立即设置：

```matlab
rocObj.plotROC(['ROC Curve - ' dataFiles{i}]);
```

这样每个标题都直接写入刚创建的图窗，避免在主程序中依赖“当前图窗”而出现标题对应错误。

## 10. testMyROC 主程序

### 10.1 路径设置

```matlab
scriptDir = fileparts(mfilename('fullpath'));
projectDir = fileparts(scriptDir);
logDir = fullfile(scriptDir, 'run_logs');
```

三个 `.mat` 数据文件位于实验一子文件夹的上一级，所以使用 `projectDir` 构造数据路径。这样不需要依赖北太天元启动时的当前工作目录。

### 10.2 运行日志

```matlab
logPath = fullfile(logDir, 'baltamatica_run_output.txt');
logFile = fopen(logPath, 'w');
fclose(logFile);
diary(logPath);
```

先清空旧日志，再使用 `diary` 记录本次命令窗口输出。程序末尾显式调用：

```matlab
diary off;
```

这里没有使用北太天元中不存在的 `onCleanup`。

### 10.3 循环处理三个数据文件

```matlab
dataFiles = {'data1.mat', 'data2.mat', 'data3.mat'};

for i = 1:numel(dataFiles)
    dataPath = fullfile(projectDir, dataFiles{i});
    data = load(dataPath);

    rocObj = MyROC(data.labels, data.scores);

    fprintf('%s: 样本数 = %d, ROC点数 = %d, AUC = %.4f\n', ...
        dataFiles{i}, numel(data.labels), numel(rocObj.FPR), rocObj.AUC);
    rocObj.plotROC(['ROC Curve - ' dataFiles{i}]);
end
```

每次循环完成四件事：

1. 加载当前数据文件。
2. 创建 `MyROC` 对象并自动完成计算。
3. 在命令窗口输出样本数、ROC 点数和 AUC。
4. 创建一个标题与当前数据对应的独立图窗。

三个数据全部处理完成后，程序输出：

```text
测试完成，请将3个图窗依次保存为data1_ROC.png、data2_ROC.png和data3_ROC.png。
```

## 11. 为什么采用手动保存 PNG

北太天元 GUI 可以正常使用 `figure` 和 `plot`，但当前安装版本中 `saveas` 未定义。为了让最终代码完全在北太天元中运行，主程序不调用 `saveas`、`print` 或 MATLAB。

运行结束后，在三个北太天元图窗中分别使用界面保存功能，保存为：

```text
data1_ROC.png
data2_ROC.png
data3_ROC.png
```

手动保存属于实验运行步骤，不影响 `MyROC` 类的计算和绘图功能。

## 13. ROC 点数为什么多两个

当前版本显式保留 `+Inf` 和 `-Inf` 两个极端阈值，因此：

```text
ROC 点数 = 唯一得分数量 + 2
```

例如 `data3.mat` 有 1748 个唯一得分，最终得到 1750 个 ROC 点。最后两个点可能都为 `(1,1)`，但重复终点不产生额外面积，不影响 `trapz` 的结果。

## 14. 最终版本的取舍

最终代码保留了与题目直接相关的内容：

1. `MyROC` 类及五个属性。
2. 构造函数自动计算。
3. 排序、同分组和累计和算法。
4. `+Inf`、`-Inf` 两个极端状态。
5. `trapz` 计算 AUC。
6. 三组指定数据的运行和绘图。
7. 北太天元 GUI 中手动保存 PNG。

最终代码删除或简化了以下非必要内容：

- 删除耗时的 `pairwiseAUC` 运行和文件。
- 删除额外的 `tie_test`，只处理题目指定的三组数据。
- 删除通用输入错误检测。
- 删除 SVG 备用导出逻辑。
- 删除 `saveas` 和其他自动保存函数。
- 删除绘图中的自定义字体、字号、线宽和装饰样式。

这些调整不会削弱题目要求，反而让代码在北太天元中运行更稳定，也更容易讲清楚。
