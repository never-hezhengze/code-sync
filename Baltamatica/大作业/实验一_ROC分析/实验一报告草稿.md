# 实验一：自定义 ROC 分析类的设计与实现

## 1. 实验目的

本实验通过设计并实现 `MyROC` 类，理解 ROC 曲线在二分类模型评估中的作用，掌握面向对象程序设计中类、属性和方法的基本使用方式，并通过程序计算假阳性率、真阳性率和 AUC。

## 2. 类设计

`MyROC` 类包含以下属性：

- `Labels`：真实类别标签，取值为 0 或 1。
- `Scores`：分类器输出的正类预测得分。
- `FPR`：不同阈值下的假阳性率。
- `TPR`：不同阈值下的真阳性率。
- `AUC`：ROC 曲线下面积。

类中包含以下方法：

- `MyROC(labels, scores)`：构造函数，完成输入检查、数据保存、ROC 计算和 AUC 计算。
- `computeROC(obj)`：计算 ROC 曲线点。
- `computeAUC(obj)`：使用梯形法计算 AUC。
- `plotROC(obj)`：绘制 ROC 曲线并标注 AUC。

## 3. ROC 计算方法

程序首先将预测得分按降序排列，并将相同得分样本作为一组处理。随后从高分到低分扫描，每处理完一个同分组，就增量更新真正例数 `TP` 和假正例数 `FP`，并记录对应的 `TPR` 和 `FPR`。

```text
[sortedScores, sortIndex] = sort(scores, 'descend');
sortedLabels = labels(sortIndex);
scoreChangeIndex = [find(diff(sortedScores) ~= 0); numel(sortedScores)];
```

当阈值为 `+Inf` 时，所有样本都被判为负类，对应 ROC 起点 `(0,0)`；当阈值逐步降低时，得分较高的样本依次进入预测正类集合；当阈值为 `-Inf` 时，所有样本都被判为正类，对应 ROC 终点 `(1,1)`。

对于每个同分组，程序计算：

```text
TPR = TP / P
FPR = FP / N
```

其中 `P` 为正类样本总数，`N` 为负类样本总数。相比逐阈值扫描全体样本，该方法只需要一次排序和一次线性扫描，时间复杂度约为 `O(n log n)`，并且能稳定处理相同预测得分。

## 4. AUC 计算方法

在得到 `FPR` 和 `TPR` 后，程序确认 `FPR` 为非递减序列，再调用梯形积分函数：

```text
AUC = trapz(FPR, TPR);
```

AUC 越接近 1，说明分类器区分正负类的能力越强；若 AUC 接近 0.5，则说明模型效果接近随机分类器。

## 5. 测试方案

主程序 `testMyROC.m` 加载三个测试文件：

- `data1.mat`
- `data2.mat`
- `data3.mat`

每个文件中均包含 `labels` 和 `scores` 变量。程序会分别创建 `MyROC` 对象，输出样本数、ROC 点数和 AUC，并将 ROC 图保存到 `results/` 文件夹。

此外，程序增加了一个 `tie_test` 测试。该测试包含大量重复得分，但正负样本的得分分布仍有差异，因此可以验证算法在重复得分场景下不仅“不崩溃”，而且能正确计算 AUC。

为进一步验证正确性，主程序加入了独立 AUC 对照：

- 使用独立文件 `pairwiseAUC.m` 按 Wilcoxon-Mann-Whitney 统计量计算 AUC。

为了兼容北太天元，主程序没有使用 `onCleanup`，也没有使用三参数 `assert`。输入检查改为 `if + error`。脚本会检测当前环境是否提供 `figure`、`plot` 和 `saveas`：如果北太天元命令行环境不提供图形函数，则跳过图像保存，只输出数值结果；如果在北太天元图形界面中运行，则可调用 `plotROC()` 生成 ROC 图片。


结果汇总如下：

| 数据集 | 样本数 | ROC点数 | AUC |
|---|---:|---:|---:|
| data1.mat | 100 | 102 | 1.0000 |
| data2.mat | 200 | 194 | 0.9464 |
| data3.mat | 2000 | 1750 | 0.9040 |
| tie_test | 12 | 5 | 0.7222 |

其中 `data1.mat` 的 AUC 为 1，说明该测试数据中正负样本可以被预测得分完全区分；`data2.mat` 和 `data3.mat` 的 AUC 均明显大于 0.5，说明分类器具有较好的区分能力。`tie_test` 的 AUC 为 0.7222，说明算法在存在大量相同得分时仍能正确处理并给出合理结果。

实际命令行输出中的 ROC 点数包含 `-Inf` 阈值对应的重复终点，因此比“唯一得分数 + 起点”多一个端点。这个设计是为了明确满足题目中“必须包含 +Inf 和 -Inf 极端情况”的要求，不影响 AUC。

程序生成的 ROC 曲线图已保存到 `results/` 文件夹，正式报告中可选取三组数据图和命令行运行截图作为结果展示。
