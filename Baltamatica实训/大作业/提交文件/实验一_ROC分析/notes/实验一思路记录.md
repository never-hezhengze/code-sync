# 实验一：自定义ROC分析类的设计与实现

## 一、实验目标

本实验设计并实现 `MyROC` 类，用于完成二分类模型的 ROC 曲线分析。类中保存真实标签、预测得分、假阳性率、真阳性率和 AUC，并提供 ROC 计算、AUC 计算和绘图方法。

## 二、文件安排

- `MyROC.m`：ROC 分析类定义文件。
- `testMyROC.m`：主程序脚本，加载测试数据并调用类方法。
- `pairwiseAUC.m`：独立 AUC 验证函数，避免依赖脚本局部函数，提高北太天元兼容性。
- `results/`：保存程序运行生成的 ROC 曲线截图。
- `notes/实验一思路记录.md`：记录实现思路，后续可整理进实验报告或 PPT。

## 三、核心实现思路

1. 构造函数接收 `labels` 和 `scores`，统一转成列向量并保存。
2. 将输入统一转换为列向量，并保存到类属性中。
3. `computeROC()` 按 `scores` 降序排序，并把相同得分样本作为一组处理。
4. 从高分到低分增量累计 `TP` 和 `FP`，每处理完一个唯一得分组就记录一个 ROC 点。
5. 在 ROC 点序列中显式保留 `+Inf` 对应的 `(0,0)` 和 `-Inf` 对应的 `(1,1)`，保证曲线完整。
6. `computeAUC()` 直接调用 `trapz(FPR, TPR)` 计算曲线下面积。
7. `plotROC()` 绘制蓝色 ROC 曲线和红色随机分类器参考线，并在图中标注 AUC。
8. `plotROC()` 绘制蓝色 ROC 曲线和红色随机分类器参考线，并在图中标注 AUC。

## 四、同分样本处理

如果逐个阈值扫描全部样本，时间复杂度接近 `O(n^2)`，且得分相同的样本容易引入重复阈值。本实验改为“排序 + 同分组增量累计”的策略：

```text
[sortedScores, sortIndex] = sort(scores, 'descend');
sortedLabels = labels(sortIndex);
scoreChangeIndex = [find(diff(sortedScores) ~= 0); numel(sortedScores)];
```

这样只需要一次排序和一次线性扫描，时间复杂度约为 `O(n log n)`。所有相同得分样本会被放在同一组中统一更新 `TP` 和 `FP`，避免同分样本顺序影响 ROC 结果。

## 五、测试设计

主程序使用 `data1.mat`、`data2.mat`、`data3.mat` 三个数据集进行验证。三个数据文件均包含 `labels` 和 `scores` 两个变量。

此外，主程序增加了一个 `tie_test`，其中大量样本具有完全相同的预测得分，但正负样本分布并不完全相同，用于验证类在“重复得分 + 仍有区分能力”的情况下能否正确计算 AUC。

主程序还加入两类对照验证：

- `pairwiseAUC()`：使用 Wilcoxon-Mann-Whitney 统计量独立验证 AUC。

## 六、实际验证结果

北太天元字符前端实际运行结果为：

- `data1.mat`：AUC = 1.0000，和 `pairwiseAUC` 差异为 0。
- `data2.mat`：AUC = 0.9464，和 `pairwiseAUC` 差异约为 `1.11e-16`。
- `data3.mat`：AUC = 0.9040，和 `pairwiseAUC` 差异约为 `2.89e-15`。
- `tie_test`：AUC = 0.7222，和 `pairwiseAUC` 差异约为 `1.11e-16`。

这些差异均属于浮点计算误差范围。
